# Blocking Findings

## CR-001 — P1: The public error contract is incomplete for structural and serialization validation

Repository evidence: the plan requires `parseArtifactReferenceV1` to reject unknown keys and validate every field, but it does not assign error codes, JSON Pointer paths, detail strings, or validation order for an invalid root value, missing fields, an invalid `location`, invalid `provider`, or cross-variant fields. It likewise requires `parseCommandEnvelopeV1` and `serializeCommandEnvelopeV1` to reject every unknown or missing envelope key, while the only schema oracle is `unknown envelope key` for `/extra` in `docs/plans/contracts/u2a1-runtime-protocol-contract.ts`. The plan's stated deterministic order covers only the envelope fields after the envelope-shape phase; it does not define that phase's outcomes. `serializeCanonicalJsonV1(value: unknown)` must also decide whether a generated byte sequence over the parser's 1,048,576-byte input limit, or a cyclic object, is rejected and with which stable result.

Failure scenario: two implementers can both satisfy the prose while returning different stable errors for the same supported public call, for example a repository-form artifact with `provider`, an envelope missing `issue_id`, or a serializer input whose canonical output exceeds the raw-byte limit. One implementation can report the parent path and another the missing or extra field path; one can use `invalid-envelope` and another `invalid-scalar`; a recursive serializer can throw on a cycle. Later consumers cannot reliably branch on the documented parse result, and focused tests have no required oracle to detect the disagreement.

Smallest required repair: add a closed fixture matrix and matching test instructions for every structural-parser shape failure and serializer-only failure. For each case, state the exact code, path, detail, and precedence. Define the accepted JavaScript object model for serialization, require cycle detection, and require serialization to reject output that cannot be accepted by `parseCanonicalJsonV1`, with its exact error result.
